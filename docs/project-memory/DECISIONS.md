# Decisions

Approved product and technical decisions. Dates are when the change merged into `main` (UTC, from git history), unless noted. Newest first. Superseded decisions are kept and marked.

| Date | Decision | Source |
|---|---|---|
| 2026-11-25 | **Voice follows the profile; no separate voice dropdown** (owner: "i just want the 10 options"). Supersedes the prompt's "independent voice and personality selection". Stored non-match voice choices are normalized to match. Replaced by a two-option Voice setting, **Online** (more natural, needs internet) or **Offline** (default): Online prefers network voices of the profile's gender, falling back so speech never stops | owner 2026-11-25 |
| 2026-11-24 | **Assistant personalization (owner).** (1) Personality affects Gemini replies only; fixed confirmations stay neutral. (2) Gender is never faked with pitch; the voice is chosen, pitch is a separate user control. (3) The app isn't officially named and the assistant's name is whatever the user sets, so **no user-visible text hardcodes "Penelope"**: assistant text uses the current name (`AppSettings.assistantName`) or first person "I"; text about the app says "this app" / "the app's settings". The Clear-codes history note is stored data and stays neutral ("cleared by you in the app"). The default profile is still named "Penelope". Guarded by `NoHardcodedAssistantNameTest` | PR #72 |
| 2026-11-22 | **Drive (Phase 3) design.** Calls are a dialer handoff only (`ACTION_DIAL`, never `ACTION_CALL`; no call, SMS, contacts or phone-state permission, no foreground service). Answering calls and calling by name are deferred. Messages are read and answered through a user-enabled notification listener, in memory only, replies via the notification's own reply action, always after spoken or on-screen confirmation, worded "sent to <app>", never "delivered". Media uses separate PLAY/PAUSE keys (never PLAY_PAUSE) or the active session, worded "I asked your media app". Vehicle controls are capability-only with no command method and are all unavailable (an OBD-II adapter is not a control channel). Message bodies never reach the transcript, logs or Gemini | Drive PR (`feature/drive-screen`), architect plan |
| 2026-11-21 | **Clear codes (Mode 04) approved.** DIY and Advanced only, never Everyday; next to Read codes; only after a successful code read of this vehicle in the current connection; only through an explicit two-step confirmation (one-shot 60 s token bound to vehicle and code read). `ReadOnlyCommandPolicy` and the console stay read-only. Engine must read 0 rpm. The car's answer is interpreted, codes are re-read and the outcome is saved to history. Vehicle-write changes need a passing safety review | Owner, 2026-11-21; Clear-codes PR, `docs/CLEAR_CODES.md` |
| 2026-11-21 | **Standing merge approval:** the owner grants Claude standing approval to merge non-ENET PRs once the quality gate and CI pass; vehicle-write changes also need a passing safety review. ENET tester PRs are excluded | Owner, 2026-11-21 |
| 2026-11-22 | **ENET is not part of Penelope until the owner clears it.** No ENET code, feature, dependency, build, CI or quality-gate step is implemented in or merged into Penelope (main) until the owner explicitly clears it. ENET work stays on the `experiment/*` branches (PR #11). Standing merge approval never covers ENET | Owner, 2026-11-22 |
| 2026-11-23 | **ENET moved to its own repository.** All ENET branches were copied unchanged to `shelmichael29/Enet-Development`; ENET PRs #49 and #55 were closed without merging and the old `experiment/*` branches are to be deleted from this repository by the owner | Owner, 2026-11-23 |
| 2026-11-21 | **Three distinct interfaces (Phase 1).** Knowledge levels keep their names (owner: Beginner = Everyday Driver, Advanced = DIY Enthusiast, Pro = Advanced / Professional); each level is plainer and more efficient than the last. Navigation per level: Everyday Home·Drive·My Vehicle·More; DIY Home·Diagnostics·Drive·Garage·More; Advanced Overview·Live Data·Diagnostics·Drive·More. Advanced / Professional is a **black and grey, no-nonsense** theme with no orb and no suggestion prompts; Penelope's two-way voice stays on every level. **Clear codes:** DIY and Advanced only, next to Read codes, available only after codes are read, with a confirmation prompt; built in its own PR with a safety review. **Phase 2:** build-your-own gauge dashboards (analog, digital, numbers; max 8 sensors each; several saved) and an "All sensors" list, for DIY and Advanced. **Phase 3:** Drive (music, texts, calls) on every level | Owner, 2026-11-21; Phase 1 PR, `docs/PHASE1_UI.md` |
| 2026-11-21 | **Gemini and personal details: automatic scrubbing (option 2).** Before service titles and problem descriptions go into Gemini's background facts, phone numbers, email addresses, street addresses, web links, VIN-like codes and labelled licence plates are replaced with "[removed]"; trouble codes, engine codes, sizes, mileage and dates are kept. People's names are not detected. What the user asks is still sent as asked. Raised 2026-11-16 (code scanning, PR #24) | Owner decision; scrubbing PR (`PersonalDetailScrubber`) |
| 2026-11-21 | **Recall accuracy:** one `RecallService` for every car and for Penelope's answers. A failed or unreadable check is always "couldn't check", never "no recalls". Every result shows its source and when it was checked. Model-level campaigns and VIN-specific status are separate; only an authoritative VIN source may say a recall is open for a VIN (none exists: NHTSA has no public recalls-by-VIN API). Repair eligibility (age, first retail sale, campaign timing, manufacturer policy) is explained but never decided: no mileage, date or VIN input to recall checks | This PR, `docs/VIN_SCANNER.md` §5 |
| 2026-11-20 | **VIN scanner and recalls:** on-device ML Kit (bundled) + CameraX, never saves images; a scanned VIN is never selected without the user's confirmation; the VIN goes only to NHTSA vPIC (never to the recalls API, Gemini, logs or crash reports; voice says the last four digits only). Recalls are searched by year/make/model and are **never labeled VIN-confirmed or outstanding**; the VIN-specific check is a link (NHTSA, plus Toyota/Lexus, Volkswagen, Mazda pages confirmed reachable). Offline falls back to the saved recall snapshot, labeled. The VIN is sent to vPIC by POST body, never in a URL. Manufacturer links stay a short verified list (owner decided, 2026-11-21) | PR #41, `docs/VIN_SCANNER.md` |
| 2026-11-19 | **Offline knowledge pack** ships in the app (codes, EPA vehicles, recall campaigns, crash ratings, symptom guides). Service bulletins, investigations, manufacturer communications and owner complaints stay off the phone (size, copyright, unverified). Recalls are always "for the model"; VIN check at nhtsa.gov/recalls. Safety stays built-in | PR #40, `docs/OFFLINE_KNOWLEDGE.md` |
| 2026-11-19 | **Gemini is the primary intelligence.** Only safety, conversation controls and connection status stay built-in; data questions are read by the app first, then explained by Gemini; fallbacks are always announced; every answer's source is logged; timeout 12 s via Remote Config (`penelope_ai_timeout_ms`) | PR #37, `docs/GEMINI_ROUTING.md` |
